# wairon 6.7.2

- `PARAM_TYPE_MISMATCH` says a plain value mismatch (one value for a list, a number for a string) in a short message ending with the fix.
- Hosted: a pack install refuses a name Windows reserves for a device (`con`, `nul`, `com1`, …) and a second pack declaring a name a pack in the same folder already declares; reinstalling under the same name still replaces it. An archive is judged by the name its `pack.yaml` declares, a refused install leaves the installed pack as it was, and a failed one puts it back (should that fail too, its copy is kept in the system temporary folder and the error names it).
- Pack installs take turns: the hosted server, `wairon host packs`, `wairon pack add`, `wairon pack bundle` and `wairon pack install` hold one install lock per packs folder, and `pack add`, `pack bundle` and `pack install` also refuse a second pack declaring an installed name. A pack store reinstall that fails puts the earlier version back.
- `wairon pack add` and a hosted install into a project refuse a name the project selects from the pack store; `wairon pack use` refuses, and `wairon pack bundle` refuses a folder holding, a pack added by path.
- Hosted: a `/web/*` read that sent `project` instead of `projectId` is told so, and the CLI reference names the web app's project pages and the reads behind them.
- Upgrading: install 6.7.2, restart or reconnect your AI tool. If a pack folder already holds two packs declaring one name, remove one of them; likewise a store selection and a pack added by path under one name.
