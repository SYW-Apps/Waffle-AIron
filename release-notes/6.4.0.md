# wairon 6.4.0

- Security: a self-service key minted without write access is now read-only. It used to act with its owner's full permissions; it is now refused everything but reading. A key minted before 6.4.0 is not read-only: revoke it and mint it again.
- Stricter undeclared exports: an exported function counts as used only when a call or reference actually reaches it, not when something of the same name is used elsewhere; a re-export publishes a name rather than using it. `wairon validate --ci` may now report exports that passed under 6.3.0.
- Dependency injection through an object of a module's functions (`{ isBreach }` passed where a port is expected) is now traced, so it no longer reports the call as unresolved.
- Renaming a component, contract, method, type or field inside a part now rewrites the part's own specs.
- Parts and member projects keep their spec write lock out of git; `wairon doctor --fix` repairs existing parts inside the project folder.
- `wairon host` refuses a weak admin token, as `wairon serve` does; a narrowed API key on `/mcp` is told that its narrowing refused the project.
- Upgrading: install 6.4.0, run `wairon validate --ci` and settle any new `UNDECLARED_PUBLIC_MEMBER`, run `wairon doctor --fix` in a project with parts, and re-mint read-only keys minted before 6.4.0.
