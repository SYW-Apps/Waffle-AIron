# wairon 6.2

- What a method states it calls is binding; where it states nothing, its routes are open and wairon says so. Declared `calls` are judged like narrative steps, briefs mark each method binding or open, and status counts both.
- `invokedBy: { kind: runtime }` on a component covers every method of it.
- `planned: true` on an `invokedBy` keeps a verb whose callers are not built yet reached, with a notice until they exist.
- A `Custom` transport Portal gets a notice that it is read as a network transport.
- Publishing a non-Portal from a subsystem is a warning (`PUBLIC_INTERFACE_NOT_PORTAL`), and can fail `--ci`.
- Agent files are written only when `rules.materializeAgentFiles: true` is stated; a project that left it unstated has its managed agent files removed on the next generate or lock.
- Per-component agents are retired: `rules.generateComponentImplementers` is ignored, and materialized agents are one owner per subsystem.
- `wairon update` on Windows stages the new build before swapping, and the upgrade report is never left half-written.
