# wairon 6.1.1

- `wairon upgrade` never leaves a wairon 5 form wairon 6 cannot read. A `sibling-subsystem` invokedBy, an export `type` and a `portalType` naming no transport are dropped, and the plan reports what to model instead; the upgrade refuses its own result if any form is left.
- A project 6.1.0 upgraded with such a form left behind is an unfinished upgrade: run `wairon upgrade` again at the top of the project to finish it, without hand edits.
- A spec file that exists but fails to parse is said so by the tools, quoting the reason, instead of "does not exist"; references into it are folded into its parse error.
- `RESERVED_IDENTIFIER` is an error only for a keyword the target language cannot escape; Rust `r#type`, C# `@class` and Kotlin backticks are the notice `RESERVED_IDENTIFIER_ESCAPED`.
- `wairon update` on Windows no longer fails when an MCP server started before the previous update still runs from the old binary.
- Moving a subsystem into a part you declared first under its id now works, instead of planning nothing; adding a part says how a subsystem gets into it.
- Python: a narrated call removed from the code is reported (matched by name, since Python is read without a type checker).
- TypeScript: a plain import used only as a type (constructor injection) no longer draws `UNDECLARED_EXPORT`.
- A project member added through the MCP server is set up for its own sessions (guide, skills, `.mcp.json`), as `wairon member add` already was.
- The MCP refusal for an unstamped project says no major stamp was found and wairon 5 is assumed.
