# wairon 6.7.0

- Shared Adapters: a subsystem can publish an Adapter with `shared: true`, and every subsystem of the project depends on it directly, with no client Adapter, `trustedLink` or Portal in front. It must be a stateless Adapter no pattern owns (`public-surface-shared`), and it stays inside its project.
- The fan-out caps (`GOD_COMPONENT`, `EXCESSIVE_DEPENDENCIES`) no longer count shared Adapters: generic I/O is not a responsibility.
- A Portal written as its own class must declare its verbs: a verb removed or renamed in the class is `UNREALIZED_METHOD`, even while a route entry still names it.
- Clearer messages: the admin lock route says why it refuses, `lock-check` points to `wairon status` for the changed specs, and shared-Adapter mistakes name their fix.
- Upgrading: install 6.7.0, run `wairon doctor --fix` and commit, restart or reconnect your AI tool, then run `wairon validate --ci`.
