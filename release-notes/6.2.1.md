# wairon 6.2.1

- The hosted credential and project registries no longer lose a write when two processes change them at once: every change holds a lock on its file, and a file that cannot be read refuses the change instead of being overwritten. The credential file is written owner-only on Linux and macOS.
- `wairon mcp install --hosted` accepts the `/mcp` address the server prints instead of writing `/mcp/mcp`.
- Every hosted store writes through a temporary file of its own, and on Windows retries the final rename while another process holds the file, so parallel writes no longer fail with `EPERM`.
- The spec-tree write lock records its host, so a holder on another machine is never judged gone by a local process id.
- `install.sh` and `install.ps1` verify the downloaded archive against its published `.sha256` and refuse to install on a mismatch.
- Releases now run their packaged binaries before publishing.
- Docs: what wairon checks and what it does not (README), a strict CI starter (`examples/ci/strict-gate.yml`), a re-measured hosting guide (one instance per data directory), a contributor path, and issue templates.
- Known limitation: the other hosted stores (permission grants, the organization and its unit placements, roles, policy, approvals and more) do not lock their writes yet; run their changes, including parallel `host project create`, one at a time. 6.2.2 fixes this.
