### Phase 6 — Tenancy & scoped administration (ACTIVE) — decisions from Robbe 2026-07-10
Make Phase-4 org units ACCESS-bearing. Approved: FULL delegated admin (scope-filtered), BUNDLE 6b (granular data-plane perms), RECURSIVE subtree.
- **Grant scope**: ProjectGrant gains optional `orgUnitId` — a grant scoped to a unit covers every project placed in that unit AND all descendant units (recursive subtree via units+placements). Third scope kind alongside projectId / '*'.
- **User membership**: HostedUserRecord gains optional `unitId` (home org unit) — user-list scoping keys on it.
- **scope_specialist** (NEW, pure, sdd_host): given a principal's grants + the org unit tree + placements, computes the in-scope project-id set and unit-id set for a permission (or ALL for a '*' super-admin grant). Centralizes scope logic (also retires the per-file carriesInstancePermission smell). Orchestrators gather org data (organization_repository) and call it.
- **6a scoped control-plane**: identity (audit/users/grants/token-mint), landscape (units/placements/relations/graph), operations (health/usage), self_service (approval:decide/list), admin (project create into unit) — each authz becomes "super-admin ('*') OR a unit-scoped grant carrying the permission," and results FILTER to the in-scope set. Several complete orchestrators gain organization_repository + scope_specialist deps. super-admin='*'; tenant owner=root-unit admin; team lead=sub-unit admin.
- **6b granular data-plane**: host_request_orchestrator enforces mcp:read vs mcp:write per tool — write sdd_* tools (add/update/delete/write/define/set/initialize/externalize/internalize/move) require mcp:write in the grant covering the bound project; read tools (get/validate/status) require mcp:read. Makes read-only project tokens real. Needs a tool read/write classification.
Loop: spec-finalize (one comprehensive pass) → review scope-resolution + data-plane-perm narratives → human lock → implement (waves) → verify + re-review (adversarial, given it's authz).
